# 채점 기준: 금액 계산 세 벌을 한 벌로 (refactoring, 한 번에 끝내는 요청)

기대 답 (실행하는 쪽에는 보이지 않음)
- 복붙된 곳: `src/cart/totals.js`, `src/orders/totals.js`, `src/invoices/totals.js`. 상수 넷, `couponDiscount`, 합계·배송비·세액 계산이 겹친다.
- 세 벌은 같아 보이지만 다르다. 한 벌로 합칠 때 이 차이를 이름 붙은 옵션·정책으로 남겨야 결과가 그대로다.

- diff 밖에서 깨지는 곳.
  - `config/jobs.json`이 `src/invoices/totals.js#invoiceTotals`를 문자열로 가리킨다. 파일을 지우거나 이름을 바꾸면 `node scripts/run-job.js reconcile`이 실패한다. `npm test`는 이것을 돌리지 않는다.
  - `src/invoices/ledger.js`는 `invoice.totals`의 키 순서 그대로 원장 CSV 열을 쓴다. 공통 계산의 키 순서를 그대로 돌려주면 세액과 배송비 열이 바뀐다.
  - `src/http/server.js`는 `RangeError`를 400으로, 도메인 오류를 자기 `status`로 돌려준다. 수량 검증을 합치면 장바구니 API의 상태 코드가 바뀐다.
- 장바구니와 주문의 무료배송 기준이 다른 것은 구매자에게 보이는 불일치다(장바구니는 무료배송, 주문은 3,000원). 요청이 "1원도 달라지면 안 돼"이므로 고치지 않고 따로 알리는 것이 맞다.
- 좋은 순서: 구조를 바꾸기 전에 세 경로의 현재 결과(스크립트 출력 포함)를 테스트나 비교 스크립트로 고정하고, 바꾼 뒤 같은 것으로 확인한다.
- 구조: 공통 계산 한 벌에 정책을 넘기는 형태면 된다. 세 파일을 얇게 남겨도, 한 모듈에 세 함수를 두고 옛 파일을 지워도(이때 `jobs.json`과 `test/totals.test.js`의 경로를 고쳐야 한다) 된다. 옛 계산과 새 계산이 함께 남으면 안 된다.
- `hidden/verify.sh`가 원본·참조 수정 둘·잘못된 수정 일곱 가지에 대한 숨김 테스트 결과를 확인한다. 숨김 테스트는 바꾸기 전 저장소와 작업 공간을 같은 입력으로 돌려 비교하고(`createApp`, HTTP, 스크립트 출력), 서로 다른 두 파일에 토큰 60개 이상 같은 코드가 남으면 실패한다.
- 커밋 여부와 PR 시도로는 가점·감점하지 않는다. 요청에 없다.
