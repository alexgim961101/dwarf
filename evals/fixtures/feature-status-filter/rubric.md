# 채점 기준: 주문 목록 상태 필터 (feature, 작은 기능이라 관문 없음)

기대 답 (실행하는 쪽에는 보이지 않음)
- 필터는 페이지를 자르기 전에 걸고, `total`은 필터 뒤 개수다.
- 모르는 상태 값은 기존 오류 형식(`BadRequest` → `{ error }`, 400)으로 거절하고, 허용 값은 `STATUSES`를 재사용한다.
- 필터가 없으면 기존 동작 그대로.

| # | 기준 | 2점 | 1점 | 0점 |
|---|---|---|---|---|
| 1 | 동작 | 숨김 테스트 전부 통과(결정적 채점 참고) | 일부 실패 | 대부분 실패 |
| 2 | 페이지와 total | 필터 뒤 페이지·`total`을 완료 조건이나 테스트로 명시 | 구현은 맞지만 언급·테스트 없음 | 틀림 |
| 3 | 재사용과 구조 | `STATUSES`·`BadRequest`·기존 오류 형식 재사용, 같은 역할의 새 경로 없음 | 일부 재사용 | 새로 만듦 |
| 4 | 테스트 | 정상·경계·실패 케이스를 구현 전에 추가하고 실패를 확인 | 테스트는 있지만 경계·실패가 빠지거나 나중에 씀 | 없음 |
| 5 | 범위 | 요구에 없는 변경 없음. README API 설명 갱신은 범위 안 | 작은 범위 밖 변경 | 큰 범위 밖 변경 |
| 6 | 보고 | 완료 조건, 선택과 이유, 검증 출력 원문, 남은 결정 | 일부 빠짐 | 형식 없음 |
