# 판정 지시

아래는 같은 개발 요청을 여러 에이전트가 각각 수행한 결과다. 실행마다 A, B, C 같은 이름만 붙어 있다. 어떤 모델·도구인지는 알 수 없고, 추측하지 않는다.

- 채점 기준표의 기준마다 0·1·2점을 주고, 점수마다 근거를 한 줄로 쓴다.
- 근거는 결정적 채점, 실행 기록(도구 호출 순서), diff에서 확인한 사실이어야 한다. 보고서가 주장했지만 이 셋으로 확인되지 않으면 확인되지 않은 것으로 본다.
- 결정적 채점의 PASS·FAIL은 사실로 받아들인다.
- 길이와 말투로 가점하지 않는다. 같은 내용이면 짧은 쪽이 낫다.
- 실행마다 "시니어 개발자에게 맡겼을 때 기대하는 수준인가"를 예·아니오로 판단하고, 아니오면 가장 큰 이유를 한 줄로 쓴다.
- 모든 실행을 같은 잣대로 한 번에 비교한다.

출력은 아래 형식의 JSON 하나만 쓴다. 코드 블록이나 다른 글은 쓰지 않는다.

{"runs":[{"label":"A","scores":{"1":2,"2":1},"reasons":{"1":"근거","2":"근거"},"senior_level":true,"main_gap":"아니오일 때 가장 큰 이유. 예면 빈 문자열"}]}
