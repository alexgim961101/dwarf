# 무인 실행

지금은 답할 사람이 없고, 답이 나중에 이어 가는 실행(`claude -p --resume`이나 대화형 세션에 이어서 넣는 요청)으로 오는 실행. eval의 `run.sh`와 파이프라인이 이렇게 돌린다.

## 알아보기

- 실행하는 쪽이 시스템 프롬프트(`--append-system-prompt`)나 요청에 무인 실행이라고 적는다. eval의 `run.sh`가 그렇게 한다.
- 적혀 있지 않아도 Claude Code에서 `AskUserQuestion` 도구가 없으면 무인 실행이다. `claude -p`가 그렇다. 이때 `TodoWrite`도 없고 `Agent`는 `Task`라는 이름으로 보인다.
- 다른 harness는 적혀 있을 때만.

## 묻지 않는다

- 위임 여부(라우터 실행 1)는 묻지 않고 매핑대로 쓴다. 요청에 정해져 있으면 그대로.
- 매핑 파일이 없으면 `agents.md`의 기본값을 쓰고 파일은 쓰지 않는다. 답변에 한 줄 적는다.
- 실행 중에 하나씩 묻지 않는다. 해석으로 진행할 수 있으면 해석을 적고 진행한다. 결과가 크게 달라지는 질문은 모아서 멈출 때 보고에 쓴다.

## 상태 파일

todo 대신 `<작업 디렉토리>/.docs/dwarf/state.md`에 둔다. 작업 디렉토리는 세션을 시작한 디렉토리다.

```
playbook: bug-fix
status: running
delegation: 사용 안 함

- [x] 1. 원인
- [ ] 2. 해결안 후보
- [ ] 8. 보고 뒤 정리
```

- playbook을 연 직후 만든다. playbook의 번호 단계를 그대로 옮기고, 라우터 실행 8(보고 뒤 정리)을 마지막 항목으로 둔다. 맞는 playbook이 없으면 `playbook: 없음`과 이유.
- 단계를 끝내면 `[x]`, 이번 요청에서 하지 않을 단계는 `skip: 이유`를 붙인다. 멈춰서 아직 하지 않은 단계는 `[ ]`로 둔다.
- 턴을 끝내기 전에 `status`를 쓴다.
  - `waiting`: 사용자 답이 있어야 이어 갈 수 있다. 관문 보고, 질문, 원인 미확정으로 멈춤.
  - `done`: 요청을 끝냈다. 멈춤 요청을 그 단계까지 마친 것도 `done`.
- 턴을 끝내기 전에 이번 보고(마지막 답변과 같은 내용)를 `<작업 디렉토리>/.docs/dwarf/report.md`에 덮어쓴다. 대화형 세션으로 돌리는 쪽(herdr 등)은 화면 대신 이 파일로 보고를 받는다.
- 이어 가는 실행은 먼저 이 파일을 읽고 `status`를 `running`으로 바꾼 뒤, `[x]`도 skip도 아닌 첫 단계부터 한다.
