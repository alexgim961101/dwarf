# 데이터 형태 먼저 (model the domain)

- 언제: 상태를 가진 로직을 쓸 때. 분기가 많아질 때. 같은 형태 가정을 여러 파일에서 반복할 때.
- 규칙: 로직을 쓰기 전에 데이터 형태를 이름 붙이고, 그것을 담을 구조를 고른다. 흩어진 조건문 대신 상태 기계, 타입이 있는 모델, 테이블·레지스트리, 리듀서, 알맞은 컬렉션에 도메인을 담는다.
- 왜: 조건문은 규칙을 코드 여기저기에 복사한다. 구조는 규칙을 한 곳에 두고, 잘못된 상태를 만들 수 없게 한다.
- 방법:
  - 가능한 상태와 전이를 먼저 나열한다. 불리언 여러 개가 조합되면 상태 하나로 바꾼다.
  - 같은 switch·if가 두 곳 이상에 있으면 테이블이나 다형성으로 모은다.
  - 외부에서 들어오는 데이터는 경계에서 한 번 파싱해 내부 타입으로 바꾸고, 안에서는 그 타입을 신뢰한다.
  - worker에게 위임할 때 brief의 "데이터 형태" 항목에 이 결정을 적어 보낸다.
- 아닌 것: 분기 두 개짜리 함수에 상태 기계를 넣는 것. 형태가 이미 명확하고 지역적이면 단순한 코드가 맞다.
