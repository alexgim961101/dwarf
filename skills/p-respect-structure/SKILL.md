# 구조 존중 (respect structure)

- 언제: 계층을 넘는 호출, 의존 방향, 공개 인터페이스·계약을 건드릴 때. 새 경로를 만들 때.
- 규칙: 기존 아키텍처의 계층·책임 분리·의존 방향·공개 계약을 따른다. 바꿔야 하면 기존 구조로 풀기 어려운 이유와 영향 범위를 먼저 설명한다. 같은 역할의 경로를 둘 두지 않는다.
- 왜: 구조는 이전 결정의 누적이다. 한 변경이 암묵적으로 깨면 다음 사람은 어느 쪽이 맞는지 모른다.
- 방법:
  - 변경 전에 그 영역의 계층과 의존 방향을 한 줄로 적는다. 변경이 그 방향을 거스르면 멈추고 설명한다.
  - 새 내부 API를 들이면 옛 호출자를 모두 옮기고 옛 경로를 같은 변경에서 지운다. 호환 shim, 임시 분기, "나중에 지울" 경로를 남기지 않는다.
  - 공개 계약(시그니처, 응답 형식, 설정 키)이 바뀌면 사용자에게 먼저 알린다.
  - 같은 역할의 별도 구현이나 새 관례를 임의로 만들지 않는다.
- 아닌 것: 구조가 요구를 막을 때 설명 없이 우회하는 것. 설명하고 바꾸는 것은 존중이다.
