# root-cause

결함이 왜 일어나는지 증거를 들어 답한다. 결과물은 재현 방법과 결함이 생기는 과정이고, 코드는 고치지 않는다. 코드를 읽고 짐작한 원인은 아직 가설이며, 실행해서 얻은 증거가 있어야 확정한다.

## 입력

- 증상: 에러 메시지, 로그, 실제로 본 잘못된 동작.
- 증상이 나타난 곳: API, UI, 배치, 테스트 중 어디에서 보였는지.
- 정상이던 시점: 회귀일 때만. 마지막으로 정상 동작한 날짜나 커밋.

## 절차

1. 재현: 증상이 나타난 곳에서 owner가 직접 재현한다. 바로 재현되지 않으면 조건을 좁히거나, 로그나 임시 코드를 넣어 값을 찍어 본다. 가끔만 일어나면 여러 번 실행해 몇 번 중 몇 번 일어나는지 적는다. 끝내 재현되지 않으면 시도한 조건을 남기고 상태를 "재현 불가"로 마친다.
2. 가설 세우기: 관련 코드가 어떻게 동작하는지 모르면 먼저 `how`로 파악한다. 가설마다 그 가설이 맞다면 실행했을 때 무엇이 보여야 하는지 적는다.
3. 가설 지우기: 확인하기 쉬운 가설부터 실행 결과, 로그, 디버거로 확인해 하나씩 지운다. 지운 가설은 왜 지웠는지와 함께 남긴다.
4. 결함이 들어온 커밋 찾기: 회귀일 때만 한다. `git bisect`로 찾고, 커밋마다 정상인지 가르는 명령으로 1단계의 재현 명령을 쓴다. 찾은 커밋을 왜 만들었는지는 `why`로 확인한다.
5. 원인 확정: 남은 가설을 "이 값이 여기서 이렇게 들어와서 저기서 이렇게 된다"처럼 파일:줄과 실행 출력으로 보인다. 문제가 처음 시작된 곳을 짚는다. 증상이 나타난 곳과 다를 수 있다(`p-fix-root-causes`).
6. 임시 코드 지우기: 넣은 로그와 임시 코드를 지우고 `git status`로 남은 변경이 없는지 본다.

## 출력 형식

- **상태:** 확정 / 재현 불가 / 원인 미확정.
- **재현:** 실행한 명령, 입력, 출력 원문. 가끔만 일어나면 몇 번 중 몇 번인지. 재현하지 못했으면 시도한 조건.
- **지운 가설:** 가설마다 지운 근거.
- **결함이 생기는 과정:** 문제가 처음 시작된 곳(파일:줄), 값이 흘러간 경로, 증거가 된 출력.
- **결함이 들어온 커밋:** 회귀일 때만. 커밋과 그 커밋을 만든 이유.
- **확인하지 못한 것:** 무엇을 왜 확인하지 못했는지.

## 경계

- 코드는 고치지 않는다. 로그와 임시 코드는 원인을 보려고 잠시 넣는 것이고 6단계에서 지운다.
- 재현하지 못하면 원인을 확정하지 않는다. "재현 불가" 상태로 마친다.
- 느리거나 자원을 많이 쓰는 문제의 병목을 측정으로 찾는 일은 `bench`가 맡는다.
