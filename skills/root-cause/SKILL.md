# root-cause

결함이 무엇 때문에 일어나는지 증거로 답한다. 산출물은 재현과 메커니즘이고 수정은 아니다. 소스를 읽고 짐작한 원인은 가설이고, 가설은 런타임 증거로만 확정한다.

## 입력

- 증상. 에러 메시지, 로그, 관찰한 잘못된 동작.
- 발생 표면. API, UI, 배치, 테스트 중 어디서 보였나.
- 선택. 정상이던 시점이나 커밋. 회귀일 때.

## 절차

1. 재현. owner가 증상이 보인 같은 표면에서 직접 재현한다. 바로 안 되면 조건을 좁히거나 계측을 넣는다. 간헐적이면 반복 실행해 발생률을 적는다. 끝내 재현되지 않으면 시도한 조건을 남기고 상태를 "재현 불가"로 끝낸다.
2. 가설을 세운다. 서브시스템을 모르면 `how`로 먼저 파악한다. 가설마다 그것이 맞으면 보여야 할 런타임 증거를 적는다.
3. 증거로 소거한다. 확인 비용이 싼 가설부터 실행·로그·디버거로 확인하고 하나씩 지운다. 지운 가설은 근거와 함께 남긴다.
4. 회귀면 도입 시점을 찾는다. `git bisect`의 판정 명령으로 1단계 재현을 쓴다. 찾은 커밋의 의도는 `why`로 확인한다.
5. 메커니즘을 확정한다. 남은 가설을 "이 값이 여기서 이렇게 들어와 저기서 이렇게 된다"로 파일:줄과 출력으로 보인다. 처음 잘못된 지점을 지목한다. 증상이 난 곳과 다를 수 있다(`p-fix-root-causes`).
6. 계측을 걷어낸다. 넣은 로그·임시 코드를 지우고 `git status`로 남은 변경이 없는지 본다.

## 출력 형식

- **상태.** 확정 / 재현 불가 / 원인 미확정.
- **재현.** 명령, 입력, 출력 원문. 간헐적이면 발생률. 재현 불가면 시도한 조건.
- **소거한 가설.** 가설마다 근거.
- **메커니즘.** 처음 잘못된 지점(파일:줄), 값이 흐르는 경로, 증거 출력.
- **도입 시점.** 회귀일 때 커밋과 그 의도.
- **미확인.** 확인하지 못한 것과 이유.

## 경계

- 수정하지 않는다. 계측은 원인을 보기 위한 임시 변경이고 6단계에서 걷어낸다.
- 재현 없이 원인을 확정하지 않는다. 재현 불가면 그 상태로 끝낸다.
- 측정으로 느림·자원 과다의 limiter를 찾는 일은 `bench`.
